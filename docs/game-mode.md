# 游戏模式：低延迟远控策略

入口为远控会话中的“控 → 画面 → 游戏模式”，支持沿用工具栏的长按排序。默认关闭，按当前服务器和远端设备分别保存；普通连接原有的画质预设不会被覆盖。模式切换指令仅在远端登录完成后发送，断线重连时重新应用。

也可在“已保存连接 → 修改连接 → 连接选项”中预先设置游戏模式，保存后应用于该服务器下的远端。会话中开启时可选择下次连接生效，或主动重新连接以尝试 UDP；需要时可能再次要求登录或二次验证。正在传输、录像、通话、使用画中画、隐私屏、断开后锁屏、IP 直连或已同意未加密的会话不会通过该按钮强行重连。取消编辑不会更改游戏设置，连接成功保存但游戏设置保存失败会单独提示。

## 做了什么

- 请求低画质、最高 60 FPS，并保留 RustDesk 原有的网络 QoS 和编码协商。公共服务器的中继连接最多请求 30 FPS，后台降帧仍优先。
- 每秒最多采样一次应用可见的压缩帧排队数量。连续两次达到 8 帧时，每次将请求上限降低 10 FPS，最低 20；连续六次不超过 2 帧时，每次恢复 5 FPS，最高 60。无法取得快照时不调整；不主动丢弃依赖帧。
- 连接在前台且没有控制菜单或软键盘遮挡时，实体鼠标和键盘的原生事件轮询目标间隔由 16 ms 缩短为 8 ms。系统调度可能使实际间隔更长；未更改按键映射、相对鼠标、加密或权限。
- 诊断开启时，游戏模式对仅含鼠标移动的队列日志进行限频，键盘、鼠标按键和重置事件仍保留原有诊断。连接信息展示请求的有效帧率上限，它不是实际 FPS 或端到端延迟。

关闭模式后恢复该连接原有的画质和帧率设置。连接失败、远端不支持、编码器负载或网络波动均可能使目标无法实现。

## 游戏连接策略

- 游戏模式按远端保存，下一次通过 ID 发起连接时优先尝试已有的 UDP/KCP 或 IPv6/KCP 候选；其他可用直连候选最多延后 350 毫秒开始，不保证服务器或对端支持 UDP。直接输入 IP/域名的监听器仍走原有 TCP 路径。
- 如果服务器提供的 UDP 地址打洞失败，客户端只重新申请一次 TCP 直连；无法直连时沿用原有中继流程。不会将 UDP 地址强行当作 TCP 地址，也不会因为回退跳过签名验证或自行同意不加密连接。启用游戏模式不会立即断开现有连接切换协议。
- 已加密的 UDP 会话中，连续至少四个独立的远端延迟报告均不低于 1200 ms，且跨越至少 12 秒时，可触发一次 TCP 重连；实际断线也可触发一次。值来自对端的网络延迟报告，不是端到端输入延迟，不保证 TCP 更快。旧样本、低 FPS、静态画面、单次尖峰不会触发。
- 连续高延迟情况下的主动重连会避开文件传输、录像、语音通话、后台、画中画、隐私屏和断开后锁屏；不加密会话、服务器或账号发生变化也不会自动切换。会话重连可能需要重新完成远端登录或二次验证。
- 连接信息分别显示实际连接方式和游戏链路策略；诊断仅记录候选种类、阶段、耗时、实际线路、回退原因及延迟样本，不记录令牌、密码或原始响应。网络延迟和丢包特征可能需要进一步实机调整，不能保证切换后一定更流畅。

## 高性能优先与手柄映射

- “控 → 画面 → 高性能优先”默认关闭，按服务器与远端设备分别记忆。开启后优先请求该连接的自定义画质参数；未设置自定义值时请求 60 FPS、100% 码率比例。它不会绕过公共中继或后台限制，也不会保证被控端一定达到请求值。
- 已保存连接的编辑界面支持选择自定义码率比例和帧率。连接信息区分别展示本端请求、实际接收速率和实际显示帧率；远端报告目标码率时另行显示。接收速率不含网络协议开销，也不等同于编码器的固定输出码率。
- “控 → 输入”可分别开启实体手柄和屏幕虚拟手柄，两者默认关闭。手柄按钮、摇杆、死区与鼠标灵敏度可设置，按服务器与远端分别保存；相同按键映射会给出冲突提示。关闭手柄、断线、切后台或失去焦点时释放相关按键。
- 外接实体手柄依赖 HarmonyOS GameControllerKit，实际可用性取决于系统版本（API 21 及以上）和设备；不可用时屏幕虚拟手柄仍可使用。本功能将手柄动作映射为远端键盘和鼠标，不是原生手柄透传。只接受原生手柄输入的游戏可能无法使用，摇杆在键盘方向映射下也不具备真正的模拟量行走。

## 对比边界

RustDesk 的 [视频 QoS](https://raw.githubusercontent.com/rustdesk/rustdesk/1.5.0/src/server/video_qos.rs) 会根据客户端上限和网络延迟调整视频；[Moonlight](https://moonlight-stream.org/) 和 [Sunshine](https://docs.lizardbyte.dev/projects/sunshine/v0.23.0/about/advanced_usage.html) 则面向游戏串流，在捕获、硬件编码、传输和呈现方面有自己的低延迟实现。本模式仍然使用 RustDesk 连接协议，并未实现 Sunshine/Moonlight 的协议、原生手柄透传或完整的游戏鼠标锁定。

排队快照是非阻塞、非原子的近似值，不包含系统解码器或显示硬件内部缓冲；也不衡量远端捕获与编码、网络排队、显示刷新及输入端到端时延。自适应策略本身不会主动丢帧，但原有队列溢出保护仍可能丢帧；不能据此承诺延迟数值，也不能保证严重积压时立即恢复或绝不花屏。

## 实机验收建议

在同一远端、相同分辨率、网络和游戏场景下，交替测试模式关闭与开启。记录实际呈现 FPS、连接方式、软／硬解、网络延迟及排队日志，并用外部高速摄像或可复现的输入到显示测量对比端到端延迟；同时检查画面花屏、按键释放、后台恢复和不同远端设置隔离。避免把请求上限或网络 RTT 误作实际画面延迟。

实体手柄应在不同机型上测试连接、断开、后台切换、按键、扳机和两个摇杆；虚拟手柄应测试触摸取消、多指同时操作以及不同窗口尺寸。测试完成前不应将自动化构建或映射测试视为设备兼容性验收。
