# 初始选屏与键盘诊断脱敏

## 现象与定位

2.0.2 的 Windows 双屏诊断显示：被控端在登录响应中返回默认屏幕索引 1，
客户端首次轮询却无条件切到索引 0，并丢弃索引 1 的后续帧。
这与用户报告的“锁屏/登录时黑屏，盲输密码进入桌面后恢复”吻合。
日志只证明有编码帧与解码输出，不能证明帧内容不是黑色；仍需同环境实机确认。

## 选屏规则

- 新建连接跟随远端登录响应的默认屏幕，不假定索引 0 是主显示器。
- 同一远控页面内的自动恢复、手动重试及游戏模式重连保留先前选择。
- 在断连轮询清除初始化状态前保存选择，避免稍后手动重试丢失目标。
- 上次屏幕失效时回退到远端默认屏幕；远端默认屏幕也无效时才选索引 0。
- 当前原生选择已经匹配时，不重复切屏或刷新采集。切屏请求失败保留目标并重试，
  不把原生层提前更新的本地索引误当成切屏成功。
- 不跨远端或跨全新远控页面持久化该临时重连选择，不改已有连接及其设置格式。

诊断字段包括 `display_reconnect_saved`、`display_restore` 和 `display_restore_refresh`。
`display_restore` 记录 requested、remote_default、selected、count、source、reason、
switch_required 和 result，便于区分首次跟随、重连恢复、目标失效及请求失败。

## 输入诊断隐私

- Rust 入队、发送前与发送后仅记录输入类别、阶段、按下/释放、模式及允许的修饰键状态。
- 所有键盘载荷（扫描码、Unicode、文本、热键编码和控制键）统一 `key=redacted`；
  不使用可被枚举反推的哈希。日志生成不修改实际发送的输入事件。
- ArkTS 与 N-API 的实体键盘、符号、快捷键和虚拟按键日志不再输出具体键值、位置或标签。
- 原生诊断写入处追加防护；导出时逐行重新脱敏当前及上一份旧日志，
  避免更新前记录的扫描码经新版本再次导出。不会删除用户的日志或连接数据。
- 保留选屏、错误结果、输入路由及修饰键状态，不记录密码、令牌、输入文本或响应原文。

## 验证范围

- `tools/test-reconnect-display.cjs`：远端非零默认屏、重连记屏、无效索引回退、重复轮询、
  同屏无操作、请求失败后重试及断连前保存。
- `tools/test-input-log-privacy.cjs`：编译运行生产 C++ 日志类，以合成数据验证写入和
  历史日志导出脱敏，保留非敏感字段并检查诊断关闭开关。
- Rust `input_diagnostics` 单元测试：不同键盘载荷输出相同的脱敏记录，
  输入消息本身不变，保留修饰键和鼠标按钮诊断。

这些自动化检查不等同于 Windows 锁屏、多屏及具体鸿蒙设备的实机验收。

- 最终代码的 123 组 JavaScript/组件回归通过；116 项 Rust 主机测试通过，
