# 个人云空间同步状态修正

## 2026-10-24：最多保留最近 5 份云备份

- 成功的同步操作（含双方无变化）自动保留按快照时间、名称确定顺序的最新 5 份；旧版 v1 固定文件也计入份数。已有超过 5 份的设备，在升级后的下一次成功同步时执行清理，单纯浏览历史、预览或确认恢复不会删除备份。
- 新快照须先等待系统同步确认，再开始清理。删除前逐一校验保留的 5 份快照；备份损坏、同步关闭、本机配置修改、云目录变化或设备时钟偏差使新快照不在保留集合时暂停清理。仅处理约定名称的历史备份，不删除 `.pending`、无关文件、本机镜像、已保存连接、分组或服务器配置。
- 删除仍由系统同步传播；等待删除同步完成并再次检查数量后才确认本次操作完成。清理失败或结果未确认时明确提示待处理，保留实际已上传／已恢复的结果，不冒充上传失败，也不冒充清理成功。异常或跨设备并发期间可能暂时超过 5 份，下次同步重试。
- 诊断仅增加清理阶段、份数上限、已删和剩余数量及安全错误码，不记录文件名、路径、主机资料、密码或密钥。
- 验证：55 组云同步隔离模拟场景、全部 88 项 Node 回归套件通过，调试 HAP 构建通过。未触碰真实华为账号或用户备份，尚未安装；多设备实际传播仍需真机验收。

## 2026-10-11：重装保护与历史备份恢复（1.2.28 / 1002028）

### 详细诊断补充

诊断默认关闭；在“设置 → 诊断日志”开启后，重试同步/恢复并导出即可采集。此次只补充可观测性，不调整恢复、删除或冲突决策。

- `request_state`：同步是否开启、是否已有同步基线、敏感信息加密开关、本机修改序号与时间、最近应用的快照时间。
- `decision_*`：没有可见云备份、首次同步优先恢复、首次冲突暂停、云端较新恢复、本机较新上传或双方一致。`request_joined` 记录合并请求关联的操作编号；等待确认、关闭与失败不会冒充上传成功。
- `inventory` / `selection_*` / `history_page`：有效快照数量、忽略项数量、是否有旧格式备份、所选版本时间与列表序号、分页结果。`history_entry_error` 保留单条备份的安全错误码；不记录名称、UUID、路径或完整确认票据。
- `backup_summary`：连接/分组数量、是否加密和是否含服务器配置。`password_missing`、`password_or_backup_invalid`、`decrypt_complete` 区分缺少密码、解密失败与成功；错误只提取数字代码，不记录密码长度、内容或原始异常文本。
- `read_size` / `read_result` / `write_size` / `write_result` / `snapshot_*`：预期和实际字节数、格式和摘要校验是否通过。不输出内容、摘要值或文件路径。
- `system_*`：系统同步基准时间、请求时间、进度状态、由新进度或新完成时间确认成功，以及失败/超时当时的状态。系统接受启动请求仍不等于同步完成。
- `restore_verify_info` / `result`：预期和实际连接/分组数量、整体字段校验、实际恢复/上传/等待密码/待处理状态。`home_reload_*` 记录首页加载、零条、完成、过期丢弃或失败；通过 `parent_op_id` 和云恢复修订号关联最近恢复操作。
- 所有附加字段为固定白名单的有限数字或布尔值，未知字段、字符串及非有限数被丢弃；详情日志不改写真正的失败阶段。诊断关闭或输出异常不会改变同步结果。

- 增加本机同步基线标记，兼容已有 `cloud-sync-last-applied-at`。未建立基线且本机没有连接、分组或服务器地址时，前台/后台/手动同步都不上传空快照；旧云数据稍后可见时优先恢复，输入解密密码不再把空本机标记成新数据。已有同步基线的用户主动清空连接，仍可正常传播删除。
- 初次同步遇到本机已编辑且云端已有数据时暂停，要求用户明确确认恢复，不直接按时间覆盖任一方。最新备份为零条连接时，新设备不会静默接受；不自动回退历史版本，避免恢复用户已删除的连接。
- 设置中的“从云端恢复”现在展示历史备份，按时间降序排列，每页 30 条，支持加载更早版本。普通备份显示连接/分组数量与是否包含服务器地址；加密备份先标注加密状态，输入密码后在预览中显示数量。损坏或未完整下载的条目标记不可恢复，保留原文件。
- 手动恢复分为预览和确认两步。预览包含日期、连接和分组数量、服务器配置状态；零条连接额外警告。确认票据绑定备份内容、当前同步设置和本机修改序号；退出、取消、改动本机配置或备份变化后，旧预览不能写入。预览等待确认期间暂停自动上传，所有操作沿用同一执行锁。
- 用户明确选择历史版本后，将其作为新的本机修改，下一次同步上传恢复后的内容，避免被较新的空快照再次覆盖。历史备份不删除、不覆盖；取消预览不修改连接和服务器数据。
- 恢复完成前核对实际写入的连接、分组、服务器字段及加密备份的凭据；未通过不报告成功。成功提示显示具体数量，空连接备份明确显示 0 条。首页异步读取增加代次和源数据检查，过期读取不能清空或回写刚恢复的连接。
- 补充默认关闭的安全诊断：空上传/空恢复被阻止、历史条目校验、预览和恢复校验阶段、连接/分组数量。日志不包含备份内容、主机名称、服务器地址、文件路径、密码、密钥或确认票据。
- 加密密码仍需用户在重装后重新输入；未开启敏感信息加密备份时，云端不包含连接密码、服务器密钥、API 登录令牌或远端系统密码。此功能不是全量应用设置恢复。

验证：云同步生产状态机通过隔离模拟覆盖重装空目录、旧备份延迟出现、最新空备份、历史预览取消/确认、历史恢复后的再同步、加密密码补输、分页、损坏条目、失效预览、写入校验失败与首页异步读取竞争。调试 HAP 可构建；真实华为账号的跨设备/卸载重装恢复与界面体验仍需真机测试。未读取或修改用户的实际云端数据，不能保证旧备份一定存在。

适用版本：1.2.10（1002010），本次不调整版本。

## 已修正

- `FileSync.start()` 仅代表系统接受启动请求，不再作为完成依据。监听实际进度并读取最近完成时间；过滤首次监听的历史状态。每个同步阶段最多等待 35 秒，超时仅显示“尚未确认完成”，不伪报成功。
- 前台自动同步、后台上传、手动同步共用执行锁。同类请求合并，恢复与同步冲突时明确提示等待，不并行写云文件。关闭同步使旧操作失效，但不会删除云备份，也不擅自终止系统自身的同步任务。
- 单独报告云服务未就绪、网络/移动数据限制、电量、云端容量、本机容量、设备温度、系统服务、目录权限及文件读写问题。未知错误显示安全错误码并建议导出诊断日志；不把所有错误解释成“未开系统开关”。
- 失败原因保留在设置页面，旧的成功时间不会覆盖新的失败提示；异常路径也会清除按钮忙碌状态。
- 日志沿用默认关闭的诊断开关。仅记录操作编号、阶段、系统状态、数字错误码及耗时，不记录原始异常文本、路径、账号、连接资料或密码。
- 本机镜像继续采用同目录临时文件、fsync 和替换重命名。云目录单独使用不可变版本快照，不再覆盖重命名已有文件；详见下节。同步期间新产生的本地修改保留为待同步状态；清空连接后不因“本地为空”反向恢复旧云备份。
- “从云端恢复”不再把本机备份镜像当作已从云端下载；本机镜像仍供系统备份使用。补输云备份密码后继续原来的上传/恢复动作。

## 验证范围

`tools/test-cloud-sync-runtime.cjs` 在模拟 SDK、内存文件及虚拟时钟下执行生产服务代码，覆盖启动与完成分离、过期回调、错误分类、超时清理、关闭同步、并发合并、编辑冲突、原子写入、敏感日志和设置页面异常状态等场景。新增 CloudDisk 不允许覆盖重命名的模拟限制，验证连续更新、跨设备快照读取、旧格式读取、SHA-256/时间戳/截断校验、短读短写、各文件操作异常、UUID 冲突及清理失败等。测试不调用真实云服务、不读取或上传真实连接数据。

编译与模拟测试不能代替真实账号验收。需要安装调试 HAP，在系统 StarRustDesk 专用同步开关已开启的手机上尝试“立即同步”。若失败，应收集新版错误码及开启诊断后的导出日志，以区分系统服务、网络限制、权限或容量问题；尚不能仅凭系统开关已开启确定实际故障根因。

## 2026-09-22：云目录 13900020 兼容性修正

用户日志中两次预同步都完成，读取旧备份、加密及本机镜像写入成功，随后在 `cloud_write` 阶段返回 13900020，尚未进入上传确认。此前阶段粒度无法证明是 fsync 还是 rename 的单次调用失败。

OpenHarmony CloudDisk 的公开实现中，目标名称已存在时，`CloudDiskMetaFile::DoRename` 内部创建新名称返回 EEXIST，上层 `CloudDiskRdbStore::Rename`/FUSE 返回 EINVAL；这与应用原先“临时文件覆盖固定名称”的更新方式不兼容。该公开源码用于定位兼容性风险，并非用户设备厂商固件的精确堆栈。模拟已复现旧写法在已有备份时失败。

- 新文件为 `cloud-sync-v2-<时间戳>-<UUID>.srdsync`；临时 `.pending` 文件不参与恢复。写入、关闭、逐字节读回校验后，仅重命名至未使用的新名称。
- 云目录不要求普通磁盘 fsync；关闭/读回仅验证本地写入，仍须等待系统 FileSync 实际完成才报告同步成功。这不是将 fsync 异常当成功忽略。
- 快照封装保存原有普通/加密备份内容及 SHA-256。SHA-256 用于完整性检查，不替代加密或身份验证；密码仍由原有 PBKDF2/AES-GCM 流程保护。
- 恢复只读取命名合规的完整快照，比较时间戳并校验内容；最新版本损坏或下载不完整时明确报错，不静默退回旧配置，避免已删除连接复活。
- 原固定文件 `cloud-sync-v1.srdsync` 保留且仍能读取；若旧客户端又写入了时间更晚的 v1 备份，新客户端也能读取。
- 新快照不会写回旧固定文件，因此旧客户端无法读取新客户端的更新。所有参与互同步的设备需要升级。此次不自动清理历史版本；快照较多时会占用额外云空间，后续保留策略需独立设计。
- 新日志细分列目录、打开、写字节、关闭、读回、校验和发布阶段。清理失败记录独立事件，不掩盖最初失败的代码和阶段；不写入路径、文件名、校验值、备份内容或凭据。

真机验收：两台设备安装同一新版，开启诊断；设备 A 连续修改/同步两次，设备 B 同步或恢复后核对结果，再反向测试。首次写入、重复更新及跨设备恢复应分别确认；模拟和构建通过并不代表真实云服务已验收。
