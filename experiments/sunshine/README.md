# 芝麻远控 · Sunshine 串流实验

本目录是芝麻远控主工程的可选调试功能。不开启测试构建时沿用原 RustDesk 页面、连接方式及云备份；
正式构建不会引入测试路由、中继地址或串流原生库。测试构建使用同一芝麻远控调试包标识，
只覆盖已验证为相同调试签名的 App，不卸载、不清数据，也不替换两款 Moonlight。
普通 RustDesk 连接入口和原生库保留。仅调试包可在「设置 → 游戏串流实验」
开启开关；默认关闭，重启后自动恢复关闭。开启后，在「连接」页进入「游戏串流 · 实验」。

使用确认过的原型源码（打包时验证 SHA-256），沿用样式、图标、页面和弹层动画；
从产品页返回时回到真实的芝麻远控连接页。无演示状态入口，无模拟播放或指标。
原生解码画面和统计由独立模块提供。页面离开、系统退后台时结束本次会话。

安装测试端、配置 Windows 助手或独立 Linux 中继，见[按设备安装与回滚](companion/deploy/SETUP.md)。手机可用、安装包可用，以及在另一台平板或笔记本上实际可用，是三种不同的验收结果；见[本轮实测](companion/deploy/ACCEPTANCE-20261124.md)。

## 本地构建

用已有的隔离 Sunshine 实验依赖目录（或检出下面的版本）；不引用实验工程的签名、设备数据、
已安装配置或测试 VPS 凭据。使用开发机的 DevEco SDK、Rust OHOS 工具链和既有调试签名，
构建前后核验签名、授权文件与此前验收过的调试包一致。

```powershell
pwsh -File experiments/sunshine/build-main-debug.ps1 -Dependencies <本机锁定的依赖根目录> -PreviousDebugHap <此前验收的同签名调试包路径> -TestBroker <已授权的临时中继地址:23388>
```

该目录应同时含有两份检出 `moonlight-common-c` 和 `ohos-openssl`；使用其原始
开源许可。分发前须单独核对对应源码、许可证和调试签名，不沿用正式版签名。
Web 界面仅加载打包资源，不允许访问外网，也不能提交地址、密钥或本地文件路径给原生模块。
测试资源和额外页面列表只生成在 `entry/src/sunshineTest/resources`。开关默认关闭并在重启时重置。
Windows 助手及实机验收可显式设置 `SESAME_STREAM_TEST_RUNTIME` 为原来已准备好的隔离测试目录，
就地使用原来 Windows 用户已配对的身份；不要将该目录、证书或凭据复制进源码。

## 单次授权边界

仍需隔离实验的 USB 控制端先完成真正的 Sunshine 配对及固定证书验证，再向测试包沙箱写入
本次会话的权限信息；本分支未把临时测试服务改成产品服务。调试授权由入口参数
`sunshineUiNonce`（24 位小写十六进制）标识。共享文件以 `.sesame-wan-<nonce>` 为前缀，
一行受限数据，读后删除，不包含账号或持久配置；仅开启开关和进入页面不会建立网络连接。

`.offer` 为旧隔离测试协议的两栏后新增一栏：一次性观察令牌（64 hex）、中继公钥（64 hex）、
本次授权的观察/中继公网 IPv4（仅本次批准的 UDP 端口 23388）。应用包内不包含具体地址。
其余 `.pub`、`.request`、`.direct`、`.timeout`、`.relay`、`.active` 与加密 RTSP
调试通道沿用实验协议。独立桌面 peer 的 `--direct` 输入在临时密钥与观察令牌之后传入观察端点。

开启局域网调试能力的测试包支持单次自动选路：校验同网段且已由配对会话授权的主机 → 公网 UDP 打洞
→ 独立加密 UDP 中继。局域网成功时不创建公网观察或中继；仅在明确没有可达候选时进入下一阶段。
候选参数有误、握手收到响应但身份未确认、加密协商失败、应用取消、或已建立的会话结束时安全停止。
这不是局域网扫描或无 USB 的首次配对，普通远控连接入口不变。

自动模式由 USB 控制端按本次 nonce 写入一次性 `.auto`（版本 `v1`）与 `.lan`。只有原生发出
`.wan-needed`，控制端才为同次连接发出原有的公网授权。公网阶段固定本次默认联网接口；蜂窝专项测试
保持原有独立入口。局域网负载测试不套用公网限速；公网会话仍不超过 1.4 Mbps，与之配套的桌面端
不超过 1.8 Mbps（含封装）。USB 只承担授权、配对和串流建连，不承载视频或实时控制。

Windows 发送端在带宽探测和低延迟发送时使用仅由测试进程持有的精细等待器，避免系统休眠粒度浪费
公网低带宽预算；不改系统计时设置。队列仍保留各路线原有带宽预算、突发限制和 125 ms 过期保护。
视频队列满或过期时按帧清除积压，不补发已丢弃帧的残片；套接字暂时不可写时仅在原截止期限内
重试同一个加密数据报。临时中继在收到包后按单调时钟结算，每方向的限速和突发上限不变。
真实屏幕测试只读取输出帧率、视频载荷和发送／接收计数；不复制或保存桌面截图。

选定路线并完成对端认证后，起流前进行不超过四档的短时下行探测。探测包只在已认证的会话内收发，
不承载屏幕内容，不转发给其他设备，也不与视频叠加；公网仍遵守原有链路限速。根据双方计数区分
未发够包、已发但未跑稳、探测到允许上限和无法得出结论。同一测试档的成功结果仅为当时的短测下限，
不是外网线路的理论峰值。按已验证速率预留余量后限制起流码率，不会超过用户请求或当前路线的策略上限。

之前隔离应用已实测通过移动数据下自动回退中继；该结果不等同于新包重新装机验收。
旧的 USB 授权公网实测不能替代现在 Windows 助手路径的验收；两条路径保留独立入口。

需显式打开 `SESAME_SUNSHINE_COMPANION=1`（与局域网测试编译开关配套）；不开启时保留

直连和中继。不更换现有 RustDesk 路由或中继，也不监听公网 Sunshine 管理端口。

## 真实主屏长测（仅本地调试包）

`SESAME_SUNSHINE_LONG_BENCH=1` 与桌面、OHOS 两侧 peer 的 `long-bench` 特性配套使用。
这个组合只用于单次 USB 授权的调试验收，媒体会话最长 920 秒；临时的中继及传输句柄也有独立到期和清理。
其他包保持原有会话时限。只在运行串流时请求当前应用窗口保持亮屏，结束或离开页面后归还，不改系统休眠配置。

验收使用实际正在显示的 Windows 主屏；不生成视频源、不截取或保存画面。局域网先做两档实流短测再选一档
长测；蜂窝中继用端上已经可用的蜂窝连接，压测保留 1.8 Mbps 链路预算。报告逐 10 秒统计实际视频载荷、
手机渲染帧率与帧缺口，编码请求、发送预算和实际收到的速率不能互换。没有足够的持续运动时只能报告当时
画面负载的结果，不能据此断定网络或编码器上限。

局域网手机视频收包可做两个只用于调试的对照。构建时用
`-UsbLanCandidate -PhoneRxTrial -CoreRxWitness` 观察播放器自己的 UDP 接收和参考帧等待；
在另一组额外加 `-NormalFecForLanTrial`，只关闭视频核心的模拟丢片自检，保留普通纠错、
加密和音频处理。两项均不改变默认构建。固定主机、素材、编码参数后，
给 `companion/check_lan_path.py` 加上 `--require-phone-rx-trial --require-core-rx`；
每组分别保存数值记录。只有独立的手机解码缺口、Windows 发包账本和播放器封账逐帧对得上时才归因。
参考[真实主屏对照与结果](companion/deploy/ACCEPTANCE-20261125-PLAYER-SOCKET-FEC.md)。

需要区分手机空闲缓冲等待与读取线程延迟时，见[手机接收与主机编码的单变量对照](companion/deploy/ACCEPTANCE-20261125-READER-DISPATCH-ENCODER.md)。
两轮原样手机可用 `companion/encoder_cue_budget.py <基线目录> <对照目录>` 核对同一段素材的实际编码；
只在独立接收线程实验包的上述构建参数后追加 `-ReaderQosTrial`。不要混合改动手机调度与主机编码预算。
运行相同 600 秒、原编码档的局域网对照时，`--expect-reader-trial initiated` 校验手机已更改并读回线程等级；
`--expect-reader-trial phase` 校验原线程设置、丢包计数完整、每个观察窗都有读包阶段记录。两者只验结果，不配置手机。
仅在原样观测确实出现“应用缓冲一直可用、套接字前后均很满并发生突发丢包”的情况下，可另用
`-BurstMarginTrial` 构建单变量试验包，并以 `--expect-reader-trial margin` 核验。只允许该档局域网的私有媒体
套接字从 1 MiB 临时增加到 1.5 MiB，必须读回实际值；拒绝、未触发、因旧包回退均单独记录。不是系统或正式版配置。

Windows 助手的 360p60 窄带中继对照可在 `check_public.py` 加
`--relay-smoothing`。只在授权的临时测试中继启用：下行加密数据最多等待 12 ms，
待发不超过 4 KiB，按原 1.8 Mbps 和原突发额度发出，等不及就丢弃。握手及手机上行不走短队列。
`result.json` 的 `relay_smoothing` 同时记录实际限速丢包与同批到达数据按旧规则计算的丢包；
后者仅是对照计数，不代表另一次实机播放。此试验不更改公网默认画质或现有 RustDesk 服务。

排查出帧间隙时，可在相同窄带对照加 `--capture-audit`。Windows 旁路只读取物理主屏的
DXGI 更新次数与时刻，不读取、保存或传出像素。`capture-audit.json` 同时记录测试 Sunshine 子进程
已知采集、编码、发包线程的状态快照，以及本次 640×360 NVENC 会话的滑动帧率与耗时。只保留角色编号
和数值，不记录程序窗口名称、凭证或视频。`minutes` 按完整分钟分别列出实际出帧与桌面更新观测，
`gaps` 将至少 250 ms 的源端间隙与屏幕更新、编码包编号及手机端处理耗时关联。
重复采样到就绪状态只能提示有调度等待，NVENC 滑动平均也不是逐帧编码耗时。缺样本时标为未归类；
少量桌面重绘不等同于持续运动。静止时保持 Sunshine 按需出帧，不为提高测试帧率而填充重复画面。

`--fresh-recovery` 仅对 360p60 窄带测试端启用。发送接口连续忙至少 150 ms 后，
Windows 保留最近 36 ms 内最新、尚未丢弃的帧，控制通道和令牌预算仍照常。手机在
已出画的流中跨过长间隙后，用帧时间戳判断是否突然收到明显积压的帧。确认过期才停止
向现有解码器提交旧帧、请求一个新的关键帧；不会因此重建流。记录请求、跳过帧数和
新关键帧实际提交显示，不记录任何画面数据。相对帧龄不能用于估算绝对显示延迟。

针对中继短时突发，在同一窄带对照下可添加 `--relay-smoothing --relay-spacing`：
Windows 中继路径按实际发出时刻计算完整的下一个封包间隔，不因晚醒或空闲缩短间隔。
保留原有总线速、队列和丢旧帧规则；直连不启用该变更。实机复测未确认能减少中继限速丢包，
因此保留为试验开关，不作为默认优化。加 `--phone-rx-audit` 要求调试包
导出每帧的两项计数：WireGuard 验证后收到的包，以及被手机本地 UDP 接收路径接受的包。
只输出帧编号、计数和等待关键帧的时刻。计数缺块或错配时不推断丢包原因；中继成功发送但
手机通道没看到，只能定位到中继之后、手机隧道验证之前，不能单独断定是运营商丢包。

排查 Windows 发包阻塞时，可在原有 `--tx-diagnostics --fresh-recovery` 上加 `--tx-guard`。
只有隔离 Windows 窄带会话启用，限制本次 UDP 套接字的发送缓冲至 8 KiB，确认不可写持续
100 ms 后改为观察可写状态、最多每 64 ms 保留一次兜底发送尝试。恢复仍受原有带宽、发包间隔
和旧帧截止时间约束，不重连、不改变中继队列。缓冲读回不符合试验范围就不算验证通过；
套接字缓冲容量不等同于网卡、路由器中的实际积压。
网关探测同时订阅现用 Wi-Fi 接口的自动配置事件，只保存时间和事件编号，不主动扫描或修改接口。
事件是否出现在停顿附近只能用于相关性分析；没有通知也不能排除驱动或无线链路的短暂异常。

构建后可用 Python Playwright 运行 `experiments/sunshine/check-ui.py`。它只给打包界面注入测试
状态，检查启停、认证失败停止、首帧门控、读取统计与返回；不会发起连接。
