# 免安装 Windows 游戏串流助手（调试）

### 1080p60 视频码率（配对调试客户端）

未自定义时请求 **20 Mbps 视频**。手机的“串流偏好”可以显式选 2–50 Mbps（整 Mbps），保存在手机本地；一次性 USB 授权的旧入口不继承此设置。带宽不足时不会把 1080p60 标准档偷偷改成低码率。首次使用应同时更新配对助手与调试客户端。

不要混淆三个数：视频编码目标、Sunshine 协议预算、手机实际呈现的视频载荷。随助手启动的锁定版本使用 20% 纠错和立体声；20,000 kbps 视频对应 26,265 kbps 协议请求，包含纠错、声音和控制开销。VPN/UDP 等额外封装仍受外层限速约束。不同画面复杂度的有效载荷可能不同，不填充视频来达到数字。

局域网和公网预算独立。公网既有低带宽/8 Mbps 配置不会自动扩大；高码率必须经过已配对端点的带宽探测，两端都允许才起流。一次性 30 Mbps 工具 `check_standard20.py` 不是生产配置：仅使用既有固定测试端点，模拟直连无响应后自动走中继，一次点击，26 秒只读串流；中继的双向合计限速、字节预算和超时相互独立，退出检查端口释放与已有服务状态。

实测验收分别记录协商值、编码器最终目标、真实解码尺寸、有效 Mbps、呈现 FPS、缺帧、最长停顿和 RTT。只有同一采样窗口内同时达到码率、帧率、无缺帧及无解码错误才算达标；单次短测不能证明持续稳定。

真实主屏和手机流量的最近一次复测，见 [20 Mbps 标准档实机报告](deploy/ACCEPTANCE-20261124-STANDARD20.md)。

高吞吐局域网的手机收包优化只用于已配对、已认证、实际收到高码率视频的调试会话。
使用非阻塞批量读取（最多 24 个，不等凑满），空闲时同时等待外层 UDP 和四个本地端口，每轮仍有控制与音频处理机会。
仍逐包验证 WireGuard，播放器、分辨率、码率偏好及公网路径不因收包方式改变。
手机诊断区分这条套接字的丢包、内核到包密度、取包等待、批次处理墙钟/线程 CPU 时间；
相关时间是同一部手机上的测量，不是两端的同步时间，不保存视频、数据报、地址或绝对内核时间。
如系统不支持批量读取则用原读法；拿不到内核时间或丢包证据时，不据此扩容。
五/十分钟的实机记录可用 `python -B experiments/sunshine/companion/analyze_lan_bursts.py <本地局域网运行目录名>` 离线复核。

提供源码启动器以及 Windows x64 独立助手和 Linux UDP 中继测试包。独立助手不需要 Python、USB 工具或开发目录；
首次使用须导入固定版本的官方 Sunshine portable ZIP。安装、首次配对、验收、限速和回退见
[测试套件安装说明](deploy/SETUP.md)。不安装 Windows 服务、不修改防火墙，也不占用原有 Sunshine 配置。

1. 在 Windows 上运行 `Start-Windows-Companion.cmd`，保持窗口打开。若有多个网络，
   按提示选择和手机同一局域网的本机 IPv4；也可通过 `--listen-ip` 指定。
2. 手机进入芝麻远控调试版的「设置 → 游戏串流实验」并打开实验功能，再回「连接」进入
   「游戏串流 · 实验」。首次把助手生成的一次性配对码粘到手机的配对框。
   配对码仅在三分钟内有效，不要发送给其他人。下次启动时从已配对电脑直接连接。
3. 串流默认使用这台 Windows 电脑的真实主屏，可在「控 → 屏幕」切换活动输出。新版独立助手和观看端可在原加密连接上续期（单次最长四小时）；旧端和定时验收按原时限。默认传输电脑播放声音，可用 `--no-audio` 禁用；
   测试结束请在助手窗口用 Ctrl+C 退出。手机和电脑不需要 USB 传输数据。

手机在系统安全存储内保留配对，电脑在当前 Windows 用户的保护下保留设备授权。
首次配对仍在同一局域网内完成。局域网地址或端口改变时，可加 `--new-invite` 重新
配对；新配对成功后会替换旧授权。连接会核对电脑身份，成功后才启用加密 UDP 串流。

## 出画后的“控”栏

串流调试页与 RustDesk 使用同一个玻璃菜单组件。没有传输实现的操作不显示；同一个按钮样式并不意味着两个协议具备同一套能力。

| 入口 | 游戏串流已接入 | 和 RustDesk 仍不同 |
| --- | --- | --- |
| 屏幕 | 枚举 Windows 活动输出，默认主屏；点选另一块后重新验证本地采集、加密出画 | 每次只传一个输出；不同时传三路，未接入 RustDesk 三指切屏、平板第二路扩展显示 |
| 输入 | 相对鼠标、绝对触摸；已授权的虚拟鼠标支持左/右键单击、中键、滚轮及相对移动；图文手势说明、鼠标速度、软键盘提交偏好 | 并非 RustDesk 全套虚拟鼠标（如面板按住左键拖动）；无剪贴板同步、手机控制及手柄映射页 |
| 键盘 | 修饰键、F1–F12、普通键和可用组合、软键盘、释放按键 | 不提供 Windows 安全注意序列 Ctrl+Alt+Del；不转发未授权的输入 |
| 画面 | 缩放、点百分比恢复 100%、放大后本地平移、全屏、支持设备上的屏幕方向 | 未接入边缘跟随、画中画、桌面窗口比例或 RustDesk 画质选项 |
| 更多 | 可拖动的连接信息；调整键盘“更多”页普通键的顺序 | 不提供 RustDesk 文件、聊天、录像和隐私屏；不支持所有工具栏任意排序 |
| 断开 | 二次确认；继续观看可取消 | 只结束当前串流，不删除配对 |

缩放、平移、设置和排序在手机本地执行；Windows 和手机均须允许输入，授权不随设置持久化。连接信息里的“初始视频请求”“已应用视频码率”“画面接收”分别对应请求值、会话应用值和实收载荷；均不是稳定带宽测定。自适应换档仅暂留本地布局，未恢复出画时不发送输入；累计帧缺口跨同次会话的换档保留。

收起不会自动吸附；将收起的「控」拖到侧边才会吸附，点击一次离开边缘，再点一次展开。全屏与方向仅在本次串流中使用，离开后恢复。只读时可以浏览键盘，不自动申请控制。

回归时用 `check_device.py --use-saved --check-toolbar` 检查共用菜单；增加 `--details-only` 可在较低负载的真实主屏串流下单查输入设置、屏幕卡片、排序入口、连接信息及取消断开。两种菜单测试都让电脑端拒绝输入；只允许截取完全位于视频区域外的本地控件。点开“键盘”只能验证按键排版和可达性，不能据此判定远端已收到按键。

## 公网实验

要开启公网选路，Windows 启动器须带 `--broker <已授权测试地址:23388>`；该地址须和调试包
构建时的 `SESAME_SUNSHINE_COMPANION_BROKER` 一致。桌面和手机端 UDP 库使用
`companion-wan` Cargo 特性（固定引入 smoltcp 0.12.0，0BSD 许可）。默认没有公网地址，
不需要、也不启动任何公网服务。已存的局域网配对可复用，无需重新配对。

受管测试助手与手机可以共用本机目标文件 `experiments/sunshine/.generated/public-test-target.json`，
仅含 `{"endpoint":"<授权 VPS 的公网 IPv4>:23388"}`。不填写密码或票据，不提交该文件。
受管 SSH 启动器只使用这一目标及现有的已知主机公钥；文件缺失或指纹不匹配时停止，不回连旧机。
用 `build-main-debug.ps1 -UseLocalTestBroker` 构建手机包；验收会检查包内两种架构是否指向同一地址。
`check_public.py --case endpoint-check` 只从电脑验证新端口的认证往返，不能代替手机流量测试。
正常测试助手的中继配置使用不超过 12 ms 的短队列平滑视频下行；上限仍为 1.8 Mbps。
对比默认 540p30 时，优化组使用 `--fresh-recovery --relay-smoothing --relay-spacing`；
直连组只指定 `--fresh-recovery`。这不改变直连优先级、加密要求、码率探测或编码纠错参数。
只有启用 `--relay-8m` 的独立测试，才可另加 `--frame-spread`。它只调整 Windows 端同一个新鲜小视频帧的分包间隔；
有别的帧在排队、队列已老化、控制包到达时都不附加这段等待。默认路径不启用，1.8 Mbps 保底和中继 12 ms 截止时间不变。

手机按「局域网 → 公网 UDP 打洞 → 加密 UDP 中继」选路，只在网络不可达时换路线。
候选已响应但没有通过身份校验、TLS 校验失败或加密协商失败时立即停止。
公网视频最高请求 1.4 Mbps，桌面发送和中继保留 1.8 Mbps 含封装预算，
视频流和加密建连共用受限通道。这里的 1.8 Mbps 是策略上限，不是带宽测速或编码载荷。

临时测试中继只接收预先登记的一对设备，仅暴露实验 UDP 23388，不开放 Sunshine 管理端口。
它得到用于匹配的角色授权，不持有配对原始凭证、Windows TLS 私钥或媒体隧道密钥。
`Start-Windows-Companion-Public.cmd` 可在本机明确启动一轮短时公网实验，不依赖 USB 或调试
手机连接；需已完成局域网配对，并能访问之前授权的测试 VPS。希望更长时间使用时需要另行布置
独立测试服务，不要把公网实验端口或账号交给不受信任的设备。
`check_public.py` 是这台测试机的验收入口；验证后会关闭临时中继并核对原有服务未重启。
不会留下长期公网服务。默认只查看画面；本机明确用 `--allow-input` 启动助手后，手机还须在出画后的
「控 → 输入」手动开启本次键鼠控制。输入沿当前已验证的加密路线走独立 TLS 会话，不新增对外端口。
局域网和已授权公网启动脚本都接受 `--allow-input`；不传该选项时保持仅查看。
断开、会话失效或心跳中断会释放由本会话按住的键和鼠标按钮，重连不重放。输入日志只记状态和数量。
输入验收可用 `check_input_routes.py`，依次使用已保存的 LAN 配对、公网直连和自动中继回退，只向专用测试
窗口发送触摸与测试文字。实际音频、实体键鼠、手柄和高权限窗口不在此验收范围。
若需要把按住 Shift 后的断线释放与较长的输入步骤分开复测，使用
`check_input_routes.py --relay-release-only`。这仍是手机流量、真实出画与自动回退；
它只证明本轮按键释放，不替代触屏或软键盘的验收。测试窗口失焦时等待或中止，不向其他窗口输入。

`check_input_routes.py --relay-observe` 在 120 秒的公网 540p30 会话中验证触摸和软键盘，
保持输入通道空闲 45 秒，再在按住修饰键时测试断线释放。日志里的 `injected=1` 表示专用窗口
主动模拟中断；`ack_silence_ms` 是最后一个有效心跳到关闭的时间，不是网络往返时延。
测试操作与画面采样分开执行。短测的 `frame_gaps` / `steady_peak_ms` 只覆盖报告的采样区间，
`session_frame_gaps` / `session_peak_ms` 是整场累计；没有连续覆盖的最大间隔报告为未知。
仅保存时间、数量和预定义阶段，不保存按键值、输入内容、证书或配对凭证。

### 十分钟实机验收（仅隔离调试）

桌面与鸿蒙端的 UDP 库使用 `companion-soak` 特性。显式执行
`check_public.py --case natural --seconds 600` 和
`check_public.py --case forced-relay --seconds 600`，分别要求实测自然直连、
以及直连无人回应后自动回退中继。第二种只控制本次测试助手不回打洞，不改路由或防火墙。
仍使用真实主屏和强制加密，公网视频请求上限 1.4 Mbps、线路预算 1.8 Mbps 不变。

长测把同一视频包在电脑发送、中继到达和中继发送各阶段的结果对照到手机报告的帧缺口。
跟踪只写数值和本轮随机化的包索引，不保存屏幕、内容、密钥或地址；测试结束时结束临时进程，
恢复手机 Wi-Fi。仅中继成功调用 UDP 发送不等于手机收到；只在跟踪完整、视频纪元匹配时做归因。
每次短会话仍按原窗口启动，长期验收不会自动开放给普通用户。

### 同带宽档位对照

在已配对的 USB 调试手机上，对 `natural` 和 `forced-relay` 各运行两次：
`check_public.py --case <路线> --profile <540p30 或 360p60> --seconds 120`。
两档分别请求 960×540／30 FPS 和 640×360／60 FPS，均使用 H.264、真实主屏、
强制媒体加密，以及同样的 1.4 Mbps 视频上限和 1.8 Mbps 线路预算。自动探测和降档仍生效；
每次降档只变码率，保留已选尺寸和目标帧率。直连测试不允许混入中继样本。

输出写入 `../.generated/public-compare/`：约 10 秒一个窗口，达到目标 FPS 的 95%、
无帧序号缺口且无渲染失败才算稳定。实际视频载荷不是请求值或线路带宽；网络 RTT
不是从输入到画面反馈的延迟。媒体数据不走 USB，结束后恢复手机原 Wi-Fi 状态。

### 指定中继的高带宽短测（隔离调试版）

操作者在本机私有目标配置中显式选择 `maxRelayKbps: 8000` 后，才可用
`--case forced-relay --profile 540p30 --seconds 120 --fresh-recovery --relay-smoothing --relay-spacing --relay-8m`。
同一配对的加密路线按 1.8、4、6、8 Mbps 逐档测量；不把服务器标称出口或短测上沿当成可持续视频码率。
留出封装、音频和纠错空间，画面请求还受用户选择和两端测量约束。旧端、无可靠样本或未指定的
中继仍保留 1.8 Mbps 线路预算。公网直连和正式版不随这个开关提档。测试结束即关闭临时中继。
默认构建保留原界面选择；用户可在串流偏好选 8 Mbps。仅为了免手动操作的手机流量验收，可在
指定本机私有目标的调试构建时同时传入 `-UseLocalTestBroker -Request8ForCellularTest`，
将本次测试界面的初始请求选为 8 Mbps；这不会覆盖已有配对或正式版偏好。

高带宽实验的中继最多暂存约 10 ms 的下行数据（8 Mbps 下 10,000 字节、最多 16 包），
仍以 12 ms 为硬期限；发送端的 4 KiB 突发额度没有增加。Windows 在队列较短时
把相邻视频包再错开半个包间隔，不让音频和控制包等待这个额外间隔。1.8 Mbps 的
保底档沿用原队列。评估时分别看探测带宽、视频请求、手机实际视频负载以及缺帧，
不能把其中任何一个当作另一个。

`--frame-spread` 仅限以上 8 Mbps 回退测试：把同一新鲜视频帧剩余的包在最多 10 ms 内错开发送；到来新帧、队列变旧或堆积时不额外等。控制和音频不受这个视频间隔约束。该选项默认关闭，不属于公网或保底档的默认策略。

2026-11-24，真实主屏、手机流量、540p30、自动回退中继：链路探测 7.79 Mbps，视频应用值由 5.9 降到 4.4 Mbps，实收均值 2.96 Mbps、29.37 FPS、RTT 中位数 43 ms。全会话 79 帧缺口中，23 帧有中继限速记录，另外 56 帧的已发送包在中继侧均有转发记录；未见队列过期。换档边界的电脑供帧间隔为 3.69 秒，应与同一档内的停顿分开看。上轮不带 `--frame-spread` 的实收为 2.13 Mbps、缺口 52 帧；两轮负载不同，不能证明额外分散发包能改善平滑性，不据此提升默认档。

### 360p60 低带宽优化试验

在 `360p60` 档显式添加 `--smooth-capture wgc --seconds 180`，分别运行自然直连和自动中继回退。
它仅改变隔离 Windows 采集进程和本次会话的发送节奏：使用 Windows Graphics Capture（可显式选
`ddx` 做对照）、650 kbps 编码上限和 768 字节媒体包设置。帧率仍取自实际主屏，最低帧率目标仍是 1；
不为了达标而增加静止画面的重复发送。桌面端在 1.8 Mbps 原限速内按包大小拉开发送间隔，保留
125 ms 队列期限、纠错和强制加密。公网默认 540p30 不使用这些试验参数。

进一步削峰时显式增加 `--peak-shave`：已认证的调试版公网 `360p60` 使用固定 500 kbps 编码预算、
768 字节媒体包，并把小帧最低纠错包数由 2 调整为 1。纠错比例、强制加密和链路上限仍保留；
小帧多包同时丢失时，能恢复的数量可能少于默认档。640 字节包试验因分片增加反而提高了单帧峰值，
不再启用。本档不在会话内升降码率，也不宣称上游支持实时改码率。其余档位继续使用原参数和
自适应逻辑。验收要求双方都只打开一段视频流，并记录每帧的封装后数据量、峰值和各端的帧缺口。

### 局域网高码率卡顿复测（仅 Windows 测试助手）

用当前项目的 `companion-soak` Windows 媒体助手，和已配对、USB 调试的测试手机运行
`python check_lan_path.py --device <USB设备号> --seconds 120`。需提前在测试手机选择
8 Mbps，保持同一 Wi-Fi 与真实主屏上的运动画面；若不能确认测试设备、强制加密、
1080p60 协商或实际播放，检查不会报告通过。USB 不转发视频；不请求键鼠授权。

报告在 `.generated/lan-compare`。分别查看带宽探测、协商值、手机实际视频有效载荷、
每 10 秒同时满足帧率和有效码率的窗口、缺帧和最长停顿。主机按帧号匹配进入发送助手和
系统接受 UDP 包的时间；这不是接收端回执，不据此断定是哪块网卡或路由器丢包。
只对完整且未换档的记录做路径归因；窗口不足、帧号不匹配或手机处理循环也有长停顿时保留未知。
诊断文件只保存时序、计数和每次测试重新生成的不可跨会话关联标签，不存画面、按键或配对凭证。

复测播放器里的「更多 → 连接信息」可加 `--monitor verify`。它在同一块展开的面板上
连续读取真实显示的指标，再关掉重开检查一次；不把后台解码日志的变化当成界面已刷新。
“最近采样”对应约一秒一次的播放器统计，帧率、收到的视频码率与 RTT 可以变化，
初始请求、应用码率和累计缺口不要求变化。面板沿用远控的半透明黑底，字体不降透明度。
